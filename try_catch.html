Manejo de excepciones

Aprende a detectar situaciones inesperadas, responder con mensajes claros y mantener el programa funcionando de forma segura.

Idea clave: una excepción no es una solución para ocultar errores. Es una señal que debemos manejar para decidir qué hacer cuando una operación no puede completarse.

1. ¿Qué es una excepción?

Una excepción es un evento que ocurre durante la ejecución y altera el flujo normal del programa. Por ejemplo: dividir entre cero, convertir texto inválido a número o acceder a una posición inexistente de un arreglo.

try

Contiene el código que puede producir una excepción.

intenta

catch

Captura una excepción y define cómo responder ante ella.

responde

finally

Se ejecuta al terminar, haya ocurrido una excepción o no.

limpia

2. Tipos principales

En este nivel conviene distinguir las excepciones que Java obliga a controlar de las que aparecen durante la ejecución.

TipoCaracterísticasEjemplos
CheckedEl compilador obliga a capturarlas o declararlas.IOException, SQLException
UncheckedOcurren durante la ejecución; normalmente revelan una condición que debemos validar.ArithmeticException, NumberFormatException
ErrorProblemas graves de la JVM o del sistema. No suelen corregirse con catch.OutOfMemoryError

Ejemplo sencillo de cada tipo

Checked

Java obliga a manejar el posible error al abrir el archivo.

try {
    FileReader archivo = new FileReader("datos.txt");
} catch (FileNotFoundException e) {
    System.out.println("Archivo no encontrado");
}

Unchecked

El programa compila, pero falla al ejecutar la operación.

int resultado = 10 / 0;
// ArithmeticException

Error

Es un problema grave de la JVM. No se recomienda provocarlo ni capturarlo.

static void repetir() {
    repetir();
}
// StackOverflowError
En palabras simples: Checked se revisa al compilar; Unchecked aparece durante la ejecución por una operación o dato inválido; Error indica un problema grave del sistema o de la JVM.
Regla práctica: captura la excepción más específica que puedas. Un catch (Exception e) demasiado general puede ocultar la causa real del problema.

3. Estructura try-catch-finally

El bloque try protege una operación; catch ofrece una respuesta y finally permite cerrar recursos o dejar una tarea terminada.

try {
    // Código que puede fallar
} catch (TipoDeExcepcion e) {
    // Respuesta ante ese problema
} finally {
    // Código de limpieza o cierre
}
Importante: el programa continúa después del catch si la excepción fue manejada. Sin un manejo adecuado, la aplicación puede terminar abruptamente.

4. Ejemplo práctico: división segura

El siguiente programa valida la entrada, captura errores diferentes y usa finally para cerrar el Scanner.

PruebaExcepciones.java ← archivo que se ejecuta

package excepciones;

import java.util.InputMismatchException;
import java.util.Scanner;

public class PruebaExcepciones {

    public static int dividir(int numerador, int denominador) {
        if (denominador == 0) {
            throw new IllegalArgumentException("El divisor no puede ser cero");
        }
        return numerador / denominador;
    }

    public static void main(String[] args) {
        Scanner teclado = new Scanner(System.in);

        try {
            System.out.print("Numerador: ");
            int numerador = teclado.nextInt();
            System.out.print("Denominador: ");
            int denominador = teclado.nextInt();

            System.out.println("Resultado: " + dividir(numerador, denominador));
        } catch (InputMismatchException e) {
            System.out.println("Error: debes ingresar números enteros.");
        } catch (IllegalArgumentException e) {
            System.out.println("Error: " + e.getMessage());
        } finally {
            teclado.close();
            System.out.println("Proceso finalizado.");
        }
    }
}

¿Qué está ocurriendo?

ElementoFunción en el ejemplo
tryIntenta leer los datos y calcular la división.
InputMismatchExceptionInforma si el usuario escribe letras en lugar de enteros.
throwLanza una excepción cuando el divisor es cero.
finallyCierra el teclado y muestra que el proceso terminó.

Posibles resultados

Numerador: 20
Denominador: 4
Resultado: 5
Proceso finalizado.
Numerador: 20
Denominador: 0
Error: El divisor no puede ser cero
Proceso finalizado.

5. Otras excepciones frecuentes

Java cuenta con muchas excepciones. Estas son algunas de las más comunes en los primeros programas:

Excepción¿Cuándo ocurre?
ArithmeticExceptionCuando se realiza una operación matemática inválida, como dividir entre cero.
NullPointerExceptionCuando se intenta utilizar un objeto que tiene el valor null.
ArrayIndexOutOfBoundsExceptionCuando se accede a una posición que no existe en un arreglo.
NumberFormatExceptionCuando se intenta convertir un texto inválido a número.
ClassCastExceptionCuando se realiza una conversión incorrecta entre objetos.
IOExceptionCuando ocurre un problema al leer o escribir archivos y datos.
FileNotFoundExceptionCuando el archivo que se desea abrir no existe.
SQLExceptionCuando ocurre un problema al trabajar con una base de datos.
Recuerda: no todas se manejan igual. Las excepciones como IOException y SQLException suelen ser verificadas; Java obliga a capturarlas o declararlas con throws.

6. Buenas prácticas

El manejo de excepciones debe hacer el código más claro y confiable, no más difícil de entender.

EvitaPrefiere
Capturar Exception para todoCapturar tipos específicos
Dejar un catch vacíoMostrar, registrar o propagar información útil
Usar excepciones para controlar cada decisiónValidar antes cuando la situación sea previsible
Mostrar el error técnico al usuarioDar un mensaje claro y amigable
Olvidar cerrar recursosUsar finally o try-with-resources

try-with-resources

Para archivos, conexiones u otros recursos, Java puede cerrarlos automáticamente.

try (Scanner teclado = new Scanner(System.in)) {
    int edad = teclado.nextInt();
    System.out.println("Edad: " + edad);
} catch (InputMismatchException e) {
    System.out.println("Ingresa una edad válida.");
}

Resumen

ConceptoIdea para recordar

catchResponde ante una excepción específica.
finallyEjecuta tareas de cierre o limpieza.
throwLanza una excepción manualmente.
throwsDeclara que un método puede propagar una excepción.
Buena prácticaValidar, informar con claridad y no ocultar errores.
