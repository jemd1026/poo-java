Conectar Java con SQL Server

Paso a paso: crear la base de datos TIENDA con la tabla personas, preparar SQL Server, conectarse desde Java con JDBC y lograr que el formulario Registro de Personas de la guía MVC guarde sus datos de forma permanente.

Idea clave: en la guía MVC las personas se guardaban en un ArrayList y se perdían al cerrar el programa. Ahora el Modelo las guardará en SQL Server. La Vista no cambia y el Controlador recibe un único ajuste.

¿Para qué conectar Java con SQL Server?

Una aplicación necesita guardar y recuperar información aunque se cierre. Java no habla directamente con SQL Server: lo hace a través de JDBC y del driver (controlador) de Microsoft.

Aplicación JavaFormulario Registro de Personas
→
JDBC + drivermssql-jdbc de Microsoft
→
SQL ServerBase TIENDA · tabla personas

Para que la conexión funcione la primera vez, todo debe estar listo en este orden. Esta guía sigue exactamente esa secuencia:

Base de datosCrear TIENDA y la tabla personas con el script.
SQL ServerAutenticación mixta, usuario de laboratorio y TCP/IP con puerto.
Proyecto JavaAgregar el driver en pom.xml y las credenciales.
ProbarEjecutar PruebaConexion y ver «Conexión exitosa».
Importante: si un paso falla, no avances al siguiente. Casi todos los errores de conexión se deben a un paso anterior omitido (servicio detenido, TCP/IP desactivado, autenticación de Windows únicamente, etc.).

¿Qué es JDBC?

JDBC (Java Database Connectivity) es la API de Java para ejecutar sentencias SQL. Se usa siempre con las mismas cinco piezas:

ElementoUso práctico
DriverManagerAbre una conexión a partir de una URL JDBC, un usuario y una contraseña.
ConnectionRepresenta la conexión abierta con SQL Server.
PreparedStatementEjecuta SQL con parámetros ? de forma segura.
ResultSetRecorre las filas que devuelve un SELECT.
SQLExceptionInforma los errores de la base de datos (conexión, login, SQL inválido...).
ConectarConexionBD.conectar() devuelve un Connection.
Prepararcn.prepareStatement(sql) y se llenan los ?.
EjecutarexecuteQuery() para leer; executeUpdate() para escribir.
Leer y cerrarSe recorre el ResultSet; try-with-resources cierra todo.
Antes se usaba JDBC-ODBC: ese puente ya no existe en Java moderno. Hoy se usa el driver JDBC oficial de Microsoft (mssql-jdbc), compatible con SQL Server 2022 y 2025.

1.1 Ejecutar el script en SSMS

  1. Abre SQL Server Management Studio (SSMS) y conéctate a tu servidor con Windows Authentication. En Server name escribe localhost (instancia predeterminada) o localhost\SQLEXPRESS (Express). En SSMS 20 o posterior, marca Trust server certificate.
  2. Abre el archivo tienda_db_sesion12.sql con File → Open → File..., o pulsa New Query y pega el script de abajo.
  3. Ejecuta las partes 1 a 4 con Execute o F5. La parte 5 (usuario) se ejecuta en el paso 2.3.
  4. En Object Explorer, clic derecho en Databases → Refresh. Debe aparecer TIENDA y, dentro de Tables, dbo.personas.

    CREATE TABLE dbo.personas (
        dni              CHAR(8)      NOT NULL,
        nombres          VARCHAR(100) NOT NULL,
        telefono         VARCHAR(9)   NULL,
        direccion        VARCHAR(150) NULL,
        email            VARCHAR(100) NULL,
        sexo             VARCHAR(10)  NOT NULL,
        profesion        VARCHAR(50)  NOT NULL,
        fecha_nacimiento DATE         NOT NULL,
        CONSTRAINT pk_personas PRIMARY KEY (dni),
        CONSTRAINT ck_personas_dni
            CHECK (LEN(dni) = 8 AND dni NOT LIKE '%[^0-9]%'),
        CONSTRAINT ck_personas_telefono
            CHECK (telefono IS NULL OR (LEN(telefono) = 9 AND telefono NOT LIKE '%[^0-9]%')),
        CONSTRAINT ck_personas_email
            CHECK (email IS NULL OR email LIKE '%_@_%._%'),
        CONSTRAINT ck_personas_sexo
            CHECK (sexo IN ('Masculino', 'Femenino')),
        CONSTRAINT ck_personas_fecha
            CHECK (fecha_nacimiento <= CAST(GETDATE() AS DATE))

END;
GO

Restricciones (CONSTRAINT): la base de datos también protege los datos. Aunque un programa tenga un error, SQL Server rechazará un DNI repetido (PRIMARY KEY), un DNI con letras, un teléfono de 5 dígitos o una fecha futura (CHECK). El Controlador valida primero; la base es la última defensa.
El script se puede ejecutar varias veces: crea la base y la tabla solo si no existen, e inserta los datos de prueba solo si la tabla está vacía. No borra información.

2. Preparar SQL Server para Java

SSMS se conecta con tu usuario de Windows y por memoria compartida. Java, en cambio, necesita usuario y contraseña de SQL Server y una conexión por TCP/IP con un puerto. Por eso SSMS puede funcionar mientras Java no. Estos pasos lo preparan.

2.1 Verificar que el servicio esté en ejecución

  1. Pulsa Windows + R y escribe SQLServerManager16.msc (SQL Server 2022) o SQLServerManager17.msc (SQL Server 2025). También puedes buscar SQL Server Configuration Manager en el menú Inicio.
  2. Selecciona SQL Server Services.
  3. Verifica que SQL Server (MSSQLSERVER) —o SQL Server (SQLEXPRESS)— diga Running. Si dice Stopped, clic derecho → Start.
Anota el nombre de tu instancia: lo que aparece entre paréntesis. MSSQLSERVER es la instancia predeterminada; SQLEXPRESS es una instancia con nombre. Lo usarás en el paso 2.4.

2.2 Activar la autenticación mixta

Por defecto SQL Server solo acepta usuarios de Windows. Java usará un usuario propio de SQL Server, así que hay que activar el modo mixto.

  1. En SSMS, en Object Explorer, clic derecho sobre el nombre del servidor (la primera línea) → Properties.
  2. Ve a la página Security.
  3. En Server authentication marca SQL Server and Windows Authentication mode y pulsa OK.
  4. Reinicia el servicio: en Object Explorer, clic derecho sobre el servidor → Restart (o desde Configuration Manager → clic derecho → Restart).
Sin reiniciar no se aplica: si omites el reinicio, Java mostrará Login failed for user 'tienda_app' aunque la contraseña sea correcta.

2.3 Crear el usuario de laboratorio tienda_app

Java no debe conectarse con sa (administrador total). Se crea un usuario que solo puede leer y escribir datos en TIENDA. Abre New Query y ejecuta la parte 5 del script, cambiando antes la contraseña:

Script · tienda_db_sesion12.sql (parte 5)

-- PARTE 5. Usuario de laboratorio para Java (NO usar la cuenta sa)
USE master;
GO
IF SUSER_ID(N'tienda_app') IS NULL
    CREATE LOGIN tienda_app
        WITH PASSWORD = N'Cambiar#Tienda2026',
             DEFAULT_DATABASE = TIENDA,
             CHECK_POLICY = ON;
GO
USE TIENDA;
GO
IF USER_ID(N'tienda_app') IS NULL
    CREATE USER tienda_app FOR LOGIN tienda_app;
ALTER ROLE db_datareader ADD MEMBER tienda_app;  -- puede leer (SELECT)
ALTER ROLE db_datawriter ADD MEMBER tienda_app;  -- puede escribir (INSERT, UPDATE, DELETE)
GO
InstrucciónQué hace
CREATE LOGINCrea la cuenta para entrar al servidor (usuario y contraseña).
CREATE USERLe da acceso a la base TIENDA.
db_datareader / db_datawriterPermisos mínimos: consultar y modificar filas, pero no borrar tablas ni crear bases.
Contraseña: con CHECK_POLICY = ON debe cumplir la política de Windows (mayúsculas, minúsculas, números y símbolos). Anótala: la usarás en el paso 3.4. No la publiques ni la subas a un repositorio.

2.4 Habilitar TCP/IP y fijar el puerto

En las ediciones Developer y Express, TCP/IP viene desactivado. Es la causa más frecuente de Connection refused.

  1. En SQL Server Configuration Manager, despliega SQL Server Network Configuration → Protocols for MSSQLSERVER (o for SQLEXPRESS).
  2. Clic derecho en TCP/IP → Enable.
  3. Clic derecho en TCP/IP → Properties → pestaña IP Addresses. Baja hasta la sección IPAll.
  4. Configura los valores según la tabla y pulsa OK.
  5. En SQL Server Services, clic derecho en el servicio de SQL Server → Restart.
IPAllValorPor qué
TCP Dynamic Portsvacío (borra el valor, incluso el 0)Un puerto dinámico cambia al reiniciar y la URL de Java dejaría de funcionar.
TCP Port1433Puerto fijo que se escribirá en la URL JDBC.
Si tienes dos instancias (por ejemplo MSSQLSERVER y SQLEXPRESS), solo una puede usar el 1433. Asigna otro puerto libre a la segunda, por ejemplo 1435, y usa ese número en la URL del paso 4.1.

2.5 Probar el usuario y el puerto desde SSMS

Antes de escribir una línea de Java, comprueba que tienda_app puede entrar por TCP/IP y por el puerto. Si esta prueba funciona, Java también funcionará.

  1. En SSMS, pulsa Connect → Database Engine...
  2. En Server name escribe localhost,1433 (con coma: así SSMS fuerza TCP/IP y ese puerto).
  3. En Authentication elige SQL Server Authentication, escribe tienda_app y su contraseña.
  4. Marca Trust server certificate y pulsa Connect.
  5. Abre New Query y ejecuta la consulta de abajo.

Consulta de verificación (conectado como tienda_app)

USE TIENDA;
SELECT DB_NAME()                            AS base_actual,
       SUSER_SNAME()                        AS usuario,
       CONNECTIONPROPERTY('net_transport')  AS protocolo,
       CONNECTIONPROPERTY('local_tcp_port') AS puerto,
       (SELECT COUNT(*) FROM dbo.personas)  AS total_personas;

Resultado esperado:

base_actual usuario protocolo puerto total_personas TIENDA tienda_app TCP 1433 5

También puedes comprobar el puerto desde PowerShell:

Test-NetConnection -ComputerName localhost -Port 1433

Debe mostrar TcpTestSucceeded : True.

Lista de comprobación antes de pasar a Java:
  • El servicio de SQL Server está en Running.
  • Existe la base TIENDA con la tabla personas y 5 filas.
  • La autenticación mixta está activa y el servicio se reinició.
  • tienda_app entra en SSMS con localhost,1433 y ve 5 personas.

3.3 ¿Por qué no escribir la contraseña en el código?

Si la contraseña está dentro de un .java, cualquiera que vea el código (un compañero, GitHub, un ZIP entregado) la conoce. Por eso Java la leerá de variables de entorno de Windows con System.getenv(...).

3.4 Crear las variables de entorno

  1. Pulsa la tecla Windows, escribe variables de entorno y abre Editar las variables de entorno de esta cuenta.
  2. En Variables de usuario, pulsa Nueva... y crea las dos variables de la tabla.
  3. Pulsa Aceptar en todas las ventanas.
  4. Cierra NetBeans por completo y vuelve a abrirlo. Los programas solo leen las variables de entorno al iniciar.
Nombre de la variableValor
TIENDA_DB_USERtienda_app

El error más común de este paso: crear las variables con NetBeans abierto. Java mostrará «Configura las variables TIENDA_DB_USER y TIENDA_DB_PASSWORD» hasta que reinicies NetBeans.

4. Conectarse desde Java

4.1 Clase ConexionBD

En registro.datos, crea la clase ConexionBD con New → Java Class. Es la única clase que conoce la dirección del servidor: si mañana cambia el puerto, se corrige solo aquí.

Archivo · ConexionBD.java (dentro del paquete registro.datos)

package registro.datos;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;

public class ConexionBD {

    // Servidor:puerto · base de datos · opciones de laboratorio
    private static final String URL =
            "jdbc:sqlserver://localhost:1433;"
            + "databaseName=TIENDA;"
            + "encrypt=true;"
            + "trustServerCertificate=true;"
            + "loginTimeout=5;";

    private ConexionBD() {
    }

    public static Connection conectar() throws SQLException {
        String usuario = System.getenv("TIENDA_DB_USER");
        String clave = System.getenv("TIENDA_DB_PASSWORD");
        if (usuario == null || clave == null) {
            throw new SQLException("Configura las variables TIENDA_DB_USER y "
                    + "TIENDA_DB_PASSWORD y reinicia NetBeans.");
        }
        return DriverManager.getConnection(URL, usuario, clave);
    }
}

La URL JDBC se lee por partes, separadas por punto y coma:

Parte de la URLSignificadoCámbiala si...
jdbc:sqlserver://Indica que se usará el driver de SQL Server.Nunca.
localhost:1433Equipo y puerto TCP (paso 2.4). Aquí se usan dos puntos, no coma como en SSMS.Usas otro puerto u otro equipo.
databaseName=TIENDABase de datos a la que se entra.Tu base tiene otro nombre.
encrypt=trueCifra la comunicación (valor por defecto en el driver actual).—
trustServerCertificate=trueAcepta el certificado local que SQL Server genera por su cuenta.Solo para laboratorio. En producción se valida un certificado real.
loginTimeout=5Si el servidor no responde en 5 segundos, falla en lugar de quedarse esperando.—
Constructor privado: ConexionBD solo tiene un método static, así que no tiene sentido crear objetos de ella. Se usa así: ConexionBD.conectar().

4.2 Clase PruebaConexion

En el mismo paquete, crea PruebaConexion. Es un programa de consola cuyo único objetivo es confirmar que la conexión funciona y mostrar con qué servidor y usuario se conectó.

Archivo · PruebaConexion.java (dentro del paquete registro.datos)

package registro.datos;

import java.sql.Connection;
import java.sql.DatabaseMetaData;
import java.sql.SQLException;

public class PruebaConexion {

    public static void main(String[] args) {
        // try-with-resources: la conexión se cierra sola al terminar el bloque
        try (Connection cn = ConexionBD.conectar()) {
            DatabaseMetaData info = cn.getMetaData();
            System.out.println("Conexión exitosa a " + cn.getCatalog());
            System.out.println("Servidor : " + info.getDatabaseProductName() + " "
                    + info.getDatabaseProductVersion());
            System.out.println("Usuario  : " + info.getUserName());
            System.out.println("Driver   : " + info.getDriverName() + " "
                    + info.getDriverVersion());
        } catch (SQLException e) {
            System.out.println("No se pudo conectar.");
            System.out.println("Mensaje : " + e.getMessage());
            System.out.println("Código  : " + e.getErrorCode());
        }
    }
}

5. Leer y guardar personas: PersonaDAO

Un DAO (Data Access Object, objeto de acceso a datos) reúne todo el SQL de una tabla en una sola clase. Así, ni la Vista ni el Controlador escriben SQL.

MétodoSQL que ejecutaMétodo JDBC
listar()SELECT ... ORDER BY nombresexecuteQuery()
buscar(dni)SELECT ... WHERE dni = ?executeQuery()
insertar(persona)INSERT INTO personas ...executeUpdate()
actualizar(persona)UPDATE personas SET ... WHERE dni = ?executeUpdate()
eliminar(dni)DELETE FROM personas WHERE dni = ?executeUpdate()

5.1 Clase PersonaDAO

En registro.datos, crea la clase PersonaDAO. Usa la clase Persona que ya existe en registro.modelo.

Archivo · PersonaDAO.java (dentro del paquete registro.datos)

package registro.datos;

import java.sql.Connection;
import java.sql.Date;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.util.ArrayList;
import java.util.List;
import registro.modelo.Persona;

public class PersonaDAO {

    private static final String SELECT =
            "SELECT dni, nombres, telefono, direccion, email, sexo, profesion, "
            + "fecha_nacimiento FROM personas ";

    public List<Persona> listar() throws SQLException {
        String sql = SELECT + "ORDER BY nombres";
        List<Persona> lista = new ArrayList<>();
        try (Connection cn = ConexionBD.conectar();
             PreparedStatement ps = cn.prepareStatement(sql);
             ResultSet rs = ps.executeQuery()) {
            while (rs.next()) {              // avanza fila por fila
                lista.add(crearPersona(rs));
            }
        }
        return lista;
    }

    public Persona buscar(String dni) throws SQLException {
        String sql = SELECT + "WHERE dni = ?";
        try (Connection cn = ConexionBD.conectar();
             PreparedStatement ps = cn.prepareStatement(sql)) {
            ps.setString(1, dni);            // reemplaza el primer ?
            try (ResultSet rs = ps.executeQuery()) {
                return rs.next() ? crearPersona(rs) : null;
            }
        }
    }

    public int insertar(Persona p) throws SQLException {
        String sql = "INSERT INTO personas (dni, nombres, telefono, direccion, email, "
                + "sexo, profesion, fecha_nacimiento) VALUES (?, ?, ?, ?, ?, ?, ?, ?)";
        try (Connection cn = ConexionBD.conectar();
             PreparedStatement ps = cn.prepareStatement(sql)) {
            ps.setString(1, p.getDni());
            ps.setString(2, p.getNombres());
            ps.setString(3, vacioANull(p.getTelefono()));
            ps.setString(4, vacioANull(p.getDireccion()));
            ps.setString(5, vacioANull(p.getEmail()));
            ps.setString(6, p.getSexo());
            ps.setString(7, p.getProfesion());
            ps.setDate(8, Date.valueOf(p.getFechaNacimiento()));
            return ps.executeUpdate();       // filas insertadas (1)
        }
    }

    public int actualizar(Persona p) throws SQLException {
        String sql = "UPDATE personas SET nombres = ?, telefono = ?, direccion = ?, "
                + "email = ?, sexo = ?, profesion = ?, fecha_nacimiento = ? WHERE dni = ?";
        try (Connection cn = ConexionBD.conectar();
             PreparedStatement ps = cn.prepareStatement(sql)) {
            ps.setString(1, p.getNombres());
            ps.setString(2, vacioANull(p.getTelefono()));
            ps.setString(3, vacioANull(p.getDireccion()));
            ps.setString(4, vacioANull(p.getEmail()));
            ps.setString(5, p.getSexo());
            ps.setString(6, p.getProfesion());
            ps.setDate(7, Date.valueOf(p.getFechaNacimiento()));
            ps.setString(8, p.getDni());     // el DNI va al final: está en el WHERE
            return ps.executeUpdate();       // 1 si existía, 0 si no
        }
    }

    public int eliminar(String dni) throws SQLException {
        String sql = "DELETE FROM personas WHERE dni = ?";
        try (Connection cn = ConexionBD.conectar();
             PreparedStatement ps = cn.prepareStatement(sql)) {
            ps.setString(1, dni);
            return ps.executeUpdate();
        }
    }

    // Convierte una fila del ResultSet en un objeto Persona
    private Persona crearPersona(ResultSet rs) throws SQLException {
        return new Persona(
                rs.getString("dni"),
                rs.getString("nombres"),
                nullAVacio(rs.getString("telefono")),
                nullAVacio(rs.getString("direccion")),
                nullAVacio(rs.getString("email")),
                rs.getString("sexo"),
                rs.getString("profesion"),
                rs.getDate("fecha_nacimiento").toLocalDate());
    }

    // Un campo opcional vacío en el formulario se guarda como NULL
    private String vacioANull(String texto) {
        return texto == null || texto.isEmpty() ? null : texto;
    }

    // Un NULL de la base se muestra como texto vacío en el formulario
    private String nullAVacio(String texto) {
        return texto == null ? "" : texto;
    }
}
Cómo se llenan los ?: se numeran desde 1, de izquierda a derecha. En actualizar hay 8 signos ?: los 7 del SET y, al final, el del WHERE dni = ?. El tipo del método debe coincidir con la columna: setString para texto y setDate para DATE.
Nunca concatenes datos en el SQL. "... WHERE dni = '" + dni + "'" permite que alguien escriba SQL dentro del formulario (inyección SQL). Con ? y setString, el driver trata el valor solo como dato.

6. Conectar el formulario MVC a la base de datos

Aquí se ve la ventaja de MVC. El Controlador usa el Modelo RegistroPersonas con cuatro métodos: agregar, modificar, eliminar y listar. Si el Modelo conserva esos mismos métodos y solo cambia dónde guarda los datos, la Vista no se entera.

VistaEl usuario completa los datos y pulsa Agregar.
ControladorValida, crea un objeto Persona y llama a modelo.agregar().
ModeloRegistroPersonas usa PersonaDAO para hacer el INSERT.
SQL ServerGuarda la fila en personas. Al reabrir, los datos siguen ahí.

6.1 Modelo: reemplazar RegistroPersonas

Abre registro.modelo.RegistroPersonas y reemplaza todo su contenido. Los métodos públicos tienen los mismos nombres y parámetros que antes; por dentro ahora usan el DAO.

Archivo · RegistroPersonas.java (dentro del paquete registro.modelo)

package registro.modelo;

import java.sql.SQLException;
import java.util.ArrayList;
import java.util.List;
import registro.datos.PersonaDAO;

public class RegistroPersonas {
    private final PersonaDAO dao = new PersonaDAO();
    private List<Persona> personas = new ArrayList<>();   // copia de la tabla

    public RegistroPersonas() {
        recargar();                       // lee la tabla al iniciar
    }

    public boolean agregar(Persona persona) {
        try {
            if (dao.buscar(persona.getDni()) != null) {
                return false;             // regla: el DNI no se repite
            }
            dao.insertar(persona);
            recargar();
            return true;
        } catch (SQLException e) {
            throw new IllegalStateException("No se pudo guardar: " + e.getMessage(), e);
        }
    }

    public boolean modificar(Persona persona) {
        try {
            boolean modificado = dao.actualizar(persona) == 1;
            recargar();
            return modificado;
        } catch (SQLException e) {
            throw new IllegalStateException("No se pudo modificar: " + e.getMessage(), e);
        }
    }

    public void eliminar(int indice) {
        try {
            dao.eliminar(personas.get(indice).getDni());
            recargar();
        } catch (SQLException e) {
            throw new IllegalStateException("No se pudo eliminar: " + e.getMessage(), e);
        }
    }

    public List<Persona> listar() {
        return personas;
    }

    private void recargar() {
        try {
            personas = dao.listar();
        } catch (SQLException e) {
            throw new IllegalStateException("No se pudo leer la tabla personas: "
                    + e.getMessage(), e);
        }
    }
}
Antes (guía MVC)Ahora (Sesión 12)
personas.add(persona)dao.insertar(persona) → INSERT
personas.set(indice, persona)dao.actualizar(persona) → UPDATE
personas.remove(indice)dao.eliminar(dni) → DELETE
Los datos se pierden al cerrarLos datos quedan en SQL Server
¿Por qué recargar()? La tabla de la Vista muestra la lista en el mismo orden que listar(). Después de cada cambio se vuelve a leer la base para que la fila número 3 de la pantalla sea la persona número 3 de la lista. Así, eliminar(int indice) sabe qué DNI borrar.
El Modelo sigue sin usar JOptionPane. Si la base falla, lanza una IllegalStateException con un mensaje claro; mostrarlo le corresponde a la Vista, a pedido del Controlador.

6.2 Controlador: mostrar los errores de la base de datos

Es el único cambio en PersonaController. Reemplaza el método actionPerformed por esta versión, que envuelve las acciones en un try-catch:

Archivo · PersonaController.java (reemplazar solo el método actionPerformed)

    @Override
    public void actionPerformed(ActionEvent e) {
        String accion = e.getActionCommand();
        try {
            if (accion.equals("Agregar")) {
                agregar();
            } else if (accion.equals("Modificar")) {
                modificar();
            } else if (accion.equals("Eliminar")) {
                eliminar();
            } else if (accion.equals("Limpiar")) {
                vista.limpiar();
            }
        } catch (IllegalStateException ex) {
            vista.mostrarMensaje(ex.getMessage());   // p. ej., SQL Server detenido
        }
    }

Los métodos agregar(), modificar(), eliminar(), leerPersona() y validar() no cambian.

Buenas prácticas

Cerrar recursos

Connection, PreparedStatement y ResultSet siempre dentro de try-with-resources.

Parámetros ?

Nunca concatenar lo que escribe el usuario dentro del SQL.

Mínimos privilegios

Un usuario propio como tienda_app; nunca sa. Contraseñas fuera del código.

Un solo lugar para la URL

Solo ConexionBD conoce el servidor, el puerto y la base.

SQL en el DAO

La Vista y el Controlador nunca escriben SELECT ni INSERT.

Doble validación

El Controlador valida para avisar al usuario; las restricciones de la tabla protegen los datos.

Pregunta de repaso 1: ¿Qué objeto recorre las filas de un SELECT?

ResultSet, avanzando con rs.next(), que devuelve false cuando ya no hay filas.

Pregunta de repaso 2: ¿Por qué SSMS se conecta y Java no?

SSMS suele entrar con autenticación de Windows y memoria compartida. Java necesita autenticación de SQL Server (modo mixto), TCP/IP habilitado y un puerto fijo.

Pregunta de repaso 3: ¿Qué diferencia hay entre executeQuery() y executeUpdate()?

executeQuery() se usa con SELECT y devuelve un ResultSet. executeUpdate() se usa con INSERT, UPDATE y DELETE y devuelve el número de filas afectadas.

Pregunta de repaso 4: ¿Por qué no se guarda la edad en la tabla?

Porque cambia con el tiempo. Se guarda la fecha de nacimiento y la edad se calcula con calcularEdad() cada vez que se muestra.
