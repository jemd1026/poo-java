Modificadores de acceso y encapsulamiento

Ejemplo práctico utilizando las clases Persona y PruebaAcceso.

1. Modificadores de acceso

Los modificadores de acceso determinan desde dónde pueden utilizarse los atributos y métodos de una clase. Permiten establecer distintos niveles de visibilidad y protección.

Modificador Acceso principal
public Puede utilizarse desde cualquier clase que tenga acceso a la clase.
protected Puede utilizarse desde clases del mismo paquete y desde subclases.
private Solamente puede utilizarse directamente dentro de la propia clase.
Importancia: los modificadores de acceso permiten proteger los datos y controlar qué elementos de una clase quedan disponibles para otras clases.

Parte 1. Modificadores de acceso en atributos

2. Clase Persona

La clase contiene tres atributos con diferentes niveles de acceso.

package encapsulamiento;

        public class Persona {

        // Atributo público: puede accederse desde otras clases
        public String nombre;

        // Atributo protegido: puede accederse desde el mismo paquete
        // y también desde las subclases
        protected int edad;

        // Atributo privado: solamente puede accederse directamente
        // desde la propia clase Persona
        private double sueldo;

        }

La visibilidad definida es:

nombre → public edad → protected sueldo → private

3. Clase PruebaAcceso

La clase PruebaAcceso pertenece al mismo paquete encapsulamiento.

package encapsulamiento;

        public class PruebaAcceso {

        public static void main(String[] args) {

        // Creación de un objeto de la clase Persona
        Persona persona = new Persona();

        // Permitido: nombre es public
        persona.nombre = "Carlos";

        // Permitido: edad es protected y ambas clases
        // pertenecen al mismo paquete
        persona.edad = 25;

        // ERROR: sueldo es private
        persona.sueldo = 2500;

        // Impresión de los atributos accesibles
        System.out.println("Nombre: " + persona.nombre);
        System.out.println("Edad: " + persona.edad);
        }
        }

persona.nombre = "Carlos"; funciona porque nombre es public. persona.edad = 25; también funciona porque edad es protected y las dos clases pertenecen al mismo paquete.

persona.sueldo = 2500; produce un error de compilación porque sueldo fue declarado como private. Un atributo privado solamente puede ser accedido directamente desde la clase donde fue declarado.

Este comportamiento introduce el concepto de ocultamiento de datos.

Parte 3. Métodos public, protected y private

Los modificadores de acceso también se aplican a los métodos de una clase. Definen desde dónde puede llamarse cada método.

4. Modificar Persona.java

Agrega los métodos con cada nivel de acceso:

package encapsulamiento;

        public class Persona {

        public String nombre;
        protected int edad;
        private double sueldo;

        // Método PUBLIC
        // Puede ser llamado desde cualquier clase
        public void metodoPublico() {
        System.out.println("Ejecutando método PUBLIC");
        }

        // Método PROTECTED
        // Puede ser llamado desde el mismo paquete
        // y también desde una subclase
        protected void metodoProtegido() {
        System.out.println("Ejecutando método PROTECTED");
        }

        // Método PRIVATE
        // Solo puede ser llamado dentro de la clase Persona
        private void metodoPrivado() {
        System.out.println("Ejecutando método PRIVATE");
        }
        }

5. Probar desde el mismo paquete

En PruebaAcceso.java, dentro del paquete encapsulamiento, llama a los métodos accesibles:

package encapsulamiento;

        public class PruebaAcceso {

        public static void main(String[] args) {

        Persona persona = new Persona();

        // Permitido: método public
        persona.metodoPublico();

        // Permitido: estamos en el mismo paquete
        persona.metodoProtegido();

        // ERROR: método private
        // persona.metodoPrivado();
        }
        }

Resultado en consola:

Ejecutando método PUBLIC
Ejecutando método PROTECTED

Al descomentar persona.metodoPrivado();, aparece un error de compilación: private void metodoPrivado() solo puede utilizarse dentro de Persona.

6. Usar el método private desde su propia clase

Agrega un método público que invoque los tres métodos desde el interior de Persona:

public void ejecutarMetodos() {

        metodoPublico();
        metodoProtegido();
        metodoPrivado();
        }

La clase completa queda así:

package encapsulamiento;

        public class Persona {

        public String nombre;
        protected int edad;
        private double sueldo;

        public void metodoPublico() {
        System.out.println("Ejecutando método PUBLIC");
        }

        protected void metodoProtegido() {
        System.out.println("Ejecutando método PROTECTED");
        }

        private void metodoPrivado() {
        System.out.println("Ejecutando método PRIVATE");
        }

        public void ejecutarMetodos() {
        metodoPublico();
        metodoProtegido();
        metodoPrivado();
        }
        }

Desde PruebaAcceso, ejecuta:

Persona persona = new Persona();

        persona.ejecutarMetodos();

Resultado en consola:

Ejecutando método PUBLIC
Ejecutando método PROTECTED
Ejecutando método PRIVATE
Concepto clave: un método private sí puede utilizarse, pero únicamente desde dentro de su propia clase.

7. Probar desde otro paquete

En Practica.java, dentro del paquete com.ucv.poo.practica, importa la clase y prueba el acceso:

package com.ucv.poo.practica;

        import encapsulamiento.Persona;

        public class Practica {

        public static void main(String[] args) {

        Persona persona = new Persona();

        // Permitido desde otro paquete
        persona.metodoPublico();

        // ERROR: pertenece a otro paquete
        // persona.metodoProtegido();

        // ERROR: solo accesible dentro de Persona
        // persona.metodoPrivado();
        }
        }

Desde otro paquete, esta llamada funciona:

persona.metodoPublico();

Resultado en consola:

Ejecutando método PUBLIC
Modificador del método Misma clase Mismo paquete Otro paquete
public Sí Sí Sí
protected Sí Sí No*
private Sí No No
*Nota sobre protected: desde otro paquete no se puede llamar directamente con persona.metodoProtegido(). El acceso es posible desde una subclase mediante herencia.

Parte 2. Acceso a los atributos desde un método

Un método definido dentro de la clase Persona puede acceder a todos sus atributos, incluso a los declarados como private.

package encapsulamiento;

        public class Persona {

        public String nombre;
        protected int edad;
        private double sueldo;

        // Método público que devuelve los datos de la persona
        public String impresion() {
        return "Nombre: " + nombre +
        "\nEdad: " + edad +
        "\nSueldo: " + sueldo;
        }
        }
Concepto clave: private no impide que el atributo sea utilizado por su propia clase. Impide el acceso directo desde otras clases.

La llamada al método desde PruebaAcceso se realiza de la siguiente manera:

package encapsulamiento;

        public class PruebaAcceso {

        public static void main(String[] args) {

        Persona persona = new Persona();

        persona.nombre = "Carlos";
        persona.edad = 25;

        // Llamada al método público de Persona
        System.out.println(persona.impresion());
        }
        }

Resultado en consola:

Nombre: Carlos
Edad: 25
Sueldo: 0.0

El sueldo muestra 0.0 porque todavía no se ha definido un mecanismo público para asignar un valor al atributo privado.

Parte 4. Encapsulamiento mediante Getter y Setter

El encapsulamiento protege el estado interno de un objeto y establece mecanismos controlados para consultar o modificar sus datos. Una práctica común consiste en declarar los atributos como private y proporcionar métodos públicos cuando sea necesario acceder a ellos.

package encapsulamiento;

        public class Persona {

        public String nombre;
        protected int edad;

        // Dato oculto
        private double sueldo;

        // SETTER: permite asignar o modificar el sueldo
        public void setSueldo(double sueldo) {
        this.sueldo = sueldo;
        }

        // GETTER: permite obtener el sueldo
        public double getSueldo() {
        return sueldo;
        }

        // Método público para devolver los datos
        public String impresion() {
        return "Nombre: " + nombre +
        "\nEdad: " + edad +
        "\nSueldo: " + sueldo;
        }
        }

4. Uso del Getter y Setter

package encapsulamiento;

        public class PruebaAcceso {

        public static void main(String[] args) {

        Persona persona = new Persona();

        persona.nombre = "Carlos";
        persona.edad = 25;

        // Asigna un valor al atributo privado mediante el setter
        persona.setSueldo(2500);

        // Muestra todos los datos
        System.out.println(persona.impresion());

        // Obtiene únicamente el sueldo mediante el getter
        System.out.println("Sueldo: " + persona.getSueldo());
        }
        }

Resultado en consola:

Nombre: Carlos
Edad: 25
Sueldo: 2500.0
Sueldo: 2500.0

5. Función de Getter y Setter

CLASE PERSONA private double sueldo ↑ ↓ SETTER GETTER ↑ ↓ modificar obtener

El método setter permite asignar o modificar el atributo:

persona.setSueldo(2500);

El método getter permite consultar u obtener su valor:

double valor = persona.getSueldo();

Parte 5. Importancia del encapsulamiento

El encapsulamiento no se limita a ocultar atributos. También permite controlar y validar los valores antes de modificar el estado de un objeto.

El setter puede incorporar una validación para impedir sueldos negativos:

public void setSueldo(double sueldo) {

        // Solo almacena valores iguales o mayores que cero
        if (sueldo >= 0) {
        this.sueldo = sueldo;
        }
        }

La siguiente instrucción puede ejecutarse:

persona.setSueldo(-500);

Sin embargo, el valor -500 no será almacenado porque no cumple la condición establecida dentro del método.

Definición: El encapsulamiento consiste en proteger el estado interno de un objeto y controlar la forma en que otras clases acceden o modifican sus datos.

8. Idea general

Una práctica habitual en programación orientada a objetos es mantener los datos protegidos y exponer únicamente las operaciones necesarias:

ATRIBUTOS → private MÉTODOS → public

Esta práctica no constituye una regla absoluta. Los modificadores se seleccionan de acuerdo con el nivel de acceso que requiera el diseño de cada clase.
