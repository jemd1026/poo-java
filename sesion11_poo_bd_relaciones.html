Bases de datos, relaciones y GRASP

Diseñar tablas relacionadas, crear paso a paso la base MARKET_DB en SQL Server y conectar ese modelo de datos con las responsabilidades de las clases Java mediante los principios GRASP.

Tablas y campos

Una tabla almacena los datos de una entidad. Cada fila es un registro y cada columna es un campo (atributo).

Ejemplo: productos

id_productodescripcionprecio_venta
1Arroz 1 kg4.80
2Azúcar 1 kg4.50
3Leche evaporada4.20

Tipos y restricciones

INT números enteros · VARCHAR(n) textos · DECIMAL(10,2) importes · DATE / DATETIME2 fechas.

NOT NULL impide valores vacíos. UNIQUE evita valores repetidos. CHECK exige una condición, por ejemplo precio_venta >= 0. DEFAULT pone un valor si no se indica.

Tabla ↔ clase: la tabla productos se parece a la clase Producto de Java: cada columna es como un atributo y cada fila es como un objeto.

Claves primarias y foráneas

Clave primaria · PK

Identifica de forma única cada registro. No puede ser nula y no se repite.

Ejemplo: clientes.id_cliente

Clave foránea · FK

Apunta a la PK de otra tabla y mantiene la integridad referencial: no deja registrar una venta de un cliente que no existe.

Ejemplo: ventas.id_cliente

Sentencias SQL

SQL permite definir estructuras, manipular datos, gestionar permisos y controlar transacciones.

DDL · Estructura

CREATE, ALTER, DROP, TRUNCATE.

-- Crea la estructura de una tabla
CREATE TABLE categorias (
  id_categoria INT IDENTITY(1,1) PRIMARY KEY,
  nombre VARCHAR(80) NOT NULL UNIQUE
);

DML · Datos

INSERT, UPDATE, DELETE; SELECT suele clasificarse como DQL.

-- Agrega, modifica y elimina filas
INSERT INTO categorias (nombre) VALUES ('Mascotas');
UPDATE categorias SET nombre = 'Mascotas y hogar'
WHERE nombre = 'Mascotas';
DELETE FROM categorias WHERE nombre = 'Mascotas y hogar';

DCL · Permisos

GRANT y REVOKE.

-- Ejemplo conceptual
GRANT SELECT ON dbo.productos TO usuario_lectura;
REVOKE SELECT ON dbo.productos FROM usuario_lectura;

TCL · Transacciones

BEGIN TRANSACTION, COMMIT, ROLLBACK y SAVE TRANSACTION.

BEGIN TRANSACTION;
UPDATE productos SET stock_actual = stock_actual - 2
WHERE id_producto = 1;
ROLLBACK TRANSACTION;  -- deshace el cambio
En SQL Server, un punto de guardado se crea con SAVE TRANSACTION nombre, no con la sentencia SAVEPOINT de otros motores.

1. Práctica: crear MARKET_DB paso a paso

Se crea la base del minimarket con 6 tablas relacionadas. El orden importa: primero las tablas que no dependen de nadie y después las que tienen claves foráneas.

categoriasclientes · empleados
→
productosFK categoría
→
ventasFK cliente · empleado
→
detalle_ventasFK venta · producto
¿Por qué ese orden? productos necesita que exista categorias para crear su FK. Si se invierte el orden, SQL Server responde que la tabla referenciada no existe.

1.1 Conectarse a SQL Server desde SSMS

  1. Abre SQL Server Management Studio (SSMS).
  2. En Server name escribe localhost (instancia predeterminada) o localhost\SQLEXPRESS (Express).
  3. En Authentication deja Windows Authentication. En SSMS 20 o posterior, marca Trust server certificate.
  4. Pulsa Connect. En Object Explorer aparecerá el servidor con la carpeta Databases.

1.2 Abrir y ejecutar el script

  1. Abre market_db_sesiones_11_12.sql con File → Open → File..., o pulsa New Query y pega el script de abajo.
  2. Pulsa Execute o F5 para ejecutar todo el script.
  3. Revisa la pestaña Messages: no debe haber mensajes en rojo.

Script · market_db_sesiones_11_12.sql

-- SESIÓN 11 · SQL Server 2022 / 2025
-- Ejecutar completo en SSMS (F5). Se puede ejecutar varias veces:
-- crea la base y las tablas solo si no existen; no borra información.
IF DB_ID(N'MARKET_DB') IS NULL
    EXEC(N'CREATE DATABASE MARKET_DB');
GO
USE MARKET_DB;
GO

-- 1. Catálogos y personas: no dependen de otras tablas.
IF OBJECT_ID(N'dbo.categorias', N'U') IS NULL
CREATE TABLE categorias (
    id_categoria INT IDENTITY(1,1) PRIMARY KEY,
    nombre VARCHAR(80) NOT NULL UNIQUE
);
IF OBJECT_ID(N'dbo.clientes', N'U') IS NULL
CREATE TABLE clientes (
    id_cliente INT IDENTITY(1,1) PRIMARY KEY,
    nombres VARCHAR(100) NOT NULL,
    apellidos VARCHAR(100) NOT NULL,
    telefono VARCHAR(15) NULL
);
IF OBJECT_ID(N'dbo.empleados', N'U') IS NULL
CREATE TABLE empleados (
    id_empleado INT IDENTITY(1,1) PRIMARY KEY,
    nombres VARCHAR(100) NOT NULL,
    apellidos VARCHAR(100) NOT NULL
);

-- 2. Productos: cada producto pertenece a una categoría.
IF OBJECT_ID(N'dbo.productos', N'U') IS NULL
CREATE TABLE productos (
    id_producto INT IDENTITY(1,1) PRIMARY KEY,
    descripcion VARCHAR(150) NOT NULL,
    precio_venta DECIMAL(10,2) NOT NULL CHECK (precio_venta >= 0),
    stock_actual INT NOT NULL DEFAULT 0 CHECK (stock_actual >= 0),
    stock_minimo INT NOT NULL DEFAULT 0 CHECK (stock_minimo >= 0),
    id_categoria INT NOT NULL,
    CONSTRAINT fk_productos_categorias FOREIGN KEY (id_categoria)
        REFERENCES categorias(id_categoria)
);

-- 3. Ventas: una venta pertenece a un cliente y un empleado.
IF OBJECT_ID(N'dbo.ventas', N'U') IS NULL
CREATE TABLE ventas (
    id_venta INT IDENTITY(1,1) PRIMARY KEY,
    fecha_venta DATETIME2(0) NOT NULL DEFAULT SYSDATETIME(),
    id_cliente INT NOT NULL,
    id_empleado INT NOT NULL,
    CONSTRAINT fk_ventas_clientes FOREIGN KEY (id_cliente)
        REFERENCES clientes(id_cliente),
    CONSTRAINT fk_ventas_empleados FOREIGN KEY (id_empleado)
        REFERENCES empleados(id_empleado)
);

-- 4. Detalle: tabla puente entre ventas y productos.
-- precio_unitario conserva el precio histórico de la venta.
IF OBJECT_ID(N'dbo.detalle_ventas', N'U') IS NULL
CREATE TABLE detalle_ventas (
    id_venta INT NOT NULL,
    id_producto INT NOT NULL,
    cantidad INT NOT NULL CHECK (cantidad > 0),
    precio_unitario DECIMAL(10,2) NOT NULL CHECK (precio_unitario >= 0),
    CONSTRAINT pk_detalle_ventas PRIMARY KEY (id_venta, id_producto),
    CONSTRAINT fk_detalle_ventas_ventas FOREIGN KEY (id_venta)
        REFERENCES ventas(id_venta),
    CONSTRAINT fk_detalle_ventas_productos FOREIGN KEY (id_producto)
        REFERENCES productos(id_producto)
);
GO

-- No se descuenta stock aquí: los datos son una carga inicial didáctica.
IF NOT EXISTS (SELECT 1 FROM ventas)
BEGIN
    BEGIN TRANSACTION;
    DECLARE @venta1 INT, @venta2 INT;
    INSERT INTO ventas (id_cliente, id_empleado)
    VALUES ((SELECT TOP (1) id_cliente FROM clientes WHERE nombres='Ana'),
            (SELECT TOP (1) id_empleado FROM empleados WHERE nombres='Pedro'));

    INSERT INTO detalle_ventas (id_venta, id_producto, cantidad, precio_unitario)
    SELECT @venta1, id_producto, 2, precio_venta FROM productos WHERE descripcion='Arroz 1 kg';

    SELECT @venta1, id_producto, 1, precio_venta FROM productos WHERE descripcion='Leche evaporada';
    INSERT INTO ventas (id_cliente, id_empleado)
    VALUES ((SELECT TOP (1) id_cliente FROM clientes WHERE nombres='Luis'),
            (SELECT TOP (1) id_empleado FROM empleados WHERE nombres='Lucía'));
    SET @venta2 = SCOPE_IDENTITY();
    INSERT INTO detalle_ventas (id_venta, id_producto, cantidad, precio_unitario)
    SELECT @venta2, id_producto, 3, precio_venta FROM productos WHERE descripcion='Agua mineral 625 ml';
    COMMIT TRANSACTION;
END;
GO

-- 7. Consultas para verificar la base creada.
SELECT p.id_producto, p.descripcion, p.precio_venta, p.stock_actual,
       c.nombre AS categoria
FROM productos AS p
INNER JOIN categorias AS c ON c.id_categoria = p.id_categoria
ORDER BY p.id_producto;

SELECT v.id_venta, v.fecha_venta, c.nombres, c.apellidos,
       SUM(d.cantidad * d.precio_unitario) AS total_venta
FROM ventas AS v
INNER JOIN clientes AS c ON c.id_cliente = v.id_cliente
INNER JOIN detalle_ventas AS d ON d.id_venta = v.id_venta
GROUP BY v.id_venta, v.fecha_venta, c.nombres, c.apellidos
ORDER BY v.id_venta;
El script se puede ejecutar varias veces: cada CREATE TABLE está protegido con IF OBJECT_ID(...) IS NULL y los datos solo se insertan si la tabla está vacía. No borra información existente.

1.6 Comprobar la integridad referencial

Las claves foráneas impiden datos «huérfanos». Abre New Query y ejecuta cada instrucción por separado (selecciónala y pulsa F5). Las dos deben fallar, y eso es lo correcto:

USE MARKET_DB;

-- Prueba A: un producto de una categoría que no existe (id 99)
INSERT INTO productos (descripcion, precio_venta, id_categoria)
VALUES ('Producto fantasma', 1.00, 99);

-- Prueba B: borrar una categoría que todavía tiene productos
DELETE FROM categorias WHERE nombre = 'Abarrotes';
PruebaMensaje esperado (Msg 547)Significado
AThe INSERT statement conflicted with the FOREIGN KEY constraint "fk_productos_categorias"No se puede apuntar a una categoría inexistente.
BThe DELETE statement conflicted with the REFERENCE constraint "fk_productos_categorias"No se puede dejar productos sin categoría.
Resultado: la base de datos protege las relaciones por sí sola. Aunque un programa tenga un error, no podrá guardar datos inconsistentes.

GRASP sin complicaciones

GRASP (General Responsibility Assignment Software Patterns, patrones generales de software para asignar responsabilidades) son nueve principios que ayudan a decidir qué clase debe hacer cada tarea. En esta sesión se practican cinco, con el mismo caso del minimarket.

1. Experto en información

La clase que tiene los datos necesarios realiza la operación.

Ejemplo: DetalleVenta calcula su subtotal.

2. Creador

Una clase crea los objetos que contiene o usa de cerca.

Ejemplo: Venta crea sus detalles.

3. Controlador

Recibe la solicitud de la interfaz y coordina el caso de uso.

Ejemplo: ControladorVenta.

4. Bajo acoplamiento

Evitar dependencias innecesarias entre clases.

Ejemplo: el controlador no conoce los detalles.

5. Alta cohesión

Cada clase mantiene responsabilidades relacionadas entre sí.

Ejemplo: Producto cuida su precio, no imprime boletas.

detalle_ventas → DetalleVenta
ventas → Venta

2.2 Clase Producto · alta cohesión

Archivo · Producto.java (dentro del paquete bodega)

package bodega;

// PRODUCTO: guarda los datos de un artículo de la bodega.
public class Producto {
    private final String nombre;   // por ejemplo, "Arroz 1 kg"
    private double precio;         // precio de venta de una unidad

    public Producto(String nombre, double precio) {
        this.nombre = nombre;
        this.precio = precio;
    }

    // GRASP 5 - ALTA COHESIÓN:
    // Producto solo administra información y reglas propias del producto.
    // No calcula ventas ni ejecuta consultas SQL.
    public void cambiarPrecio(double nuevoPrecio) {
        if (nuevoPrecio >= 0) {
            this.precio = nuevoPrecio;
        }
    }

    public String getNombre() {
        return nombre;
    }

    public double getPrecio() {
        return precio;
    }
}

2.3 Clase DetalleVenta · experto en información

Archivo · DetalleVenta.java (dentro del paquete bodega)

package bodega;

// DETALLEVENTA: un producto incluido en una venta (como una fila de detalle_ventas).
public class DetalleVenta {
    private final Producto producto;
    private final int cantidad;

    public DetalleVenta(Producto producto, int cantidad) {
        this.producto = producto;
        this.cantidad = cantidad;
    }

    // GRASP 1 - EXPERTO EN INFORMACIÓN:
    // Calcula el subtotal porque es quien conoce el producto y la cantidad.
    public double subtotal() {
        return producto.getPrecio() * cantidad;   // 4.80 × 2 = 9.60
    }

    public Producto getProducto() {
        return producto;
    }

    public int getCantidad() {
        return cantidad;
    }
}

2.4 Clase Venta · creador

Archivo · Venta.java (dentro del paquete bodega)

package bodega;

import java.util.ArrayList;
import java.util.List;

// VENTA: reúne todos los productos comprados en una operación.
public class Venta {
    private final List<DetalleVenta> detalles = new ArrayList<>();

    // GRASP 2 - CREADOR:
    // Venta crea cada DetalleVenta porque es quien los contiene.
    public void agregar(Producto producto, int cantidad) {
        detalles.add(new DetalleVenta(producto, cantidad));
    }

    // Suma los subtotales: cada detalle calcula el suyo (experto en información).
    public double total() {
        double suma = 0;
        for (DetalleVenta detalle : detalles) {
            suma += detalle.subtotal();
        }
        return suma;
    }

    public List<DetalleVenta> getDetalles() {
        return detalles;
    }
}

2.5 Clase ControladorVenta · controlador y bajo acoplamiento

Archivo · ControladorVenta.java (dentro del paquete bodega)

package bodega;

// GRASP 3 - CONTROLADOR:
// Recibe la solicitud de la interfaz y coordina la operación.
// GRASP 4 - BAJO ACOPLAMIENTO:
// No recorre los detalles ni conoce la fórmula: solo usa total() de Venta.
// Si mañana cambia el cálculo (descuentos, IGV), este código no cambia.
public class ControladorVenta {

    public double calcularTotal(Venta venta) {
        return venta.total();
    }
}

2.6 Clase Main: ejecutar y probar

Archivo · Main.java (dentro del paquete bodega)

package bodega;

public class Main {
    public static void main(String[] args) {
        Producto arroz = new Producto("Arroz 1 kg", 4.80);
        Producto leche = new Producto("Leche evaporada", 4.20);

        // La misma venta 1 de MARKET_DB: 2 arroces y 1 leche
        Venta venta = new Venta();
        venta.agregar(arroz, 2);
        venta.agregar(leche, 1);

        for (DetalleVenta d : venta.getDetalles()) {
            System.out.printf("%-16s x %d = S/ %.2f%n",
                    d.getProducto().getNombre(), d.getCantidad(), d.subtotal());
        }

        ControladorVenta controlador = new ControladorVenta();
        System.out.printf("Total de la venta: S/ %.2f%n", controlador.calcularTotal(venta));

        arroz.cambiarPrecio(-5);   // alta cohesión: Producto rechaza un precio inválido
        System.out.printf("Precio del arroz tras intentar -5: S/ %.2f%n", arroz.getPrecio());
    }
}

Arroz 1 kg x 2 = S/ 9.60 Leche evaporada x 1 = S/ 4.20 Total de la venta: S/ 13.80 Precio del arroz tras intentar -5: S/ 4.80
Coma o punto decimal: printf usa la configuración regional de Windows; en algunos equipos verás 13,80. En una aplicación comercial, los importes se manejan con BigDecimal en lugar de double.
Mismo total en Java y en SQL: la grilla 2 de MARKET_DB mostró 13.80 para la venta 1. Java llega al mismo resultado con objetos: Venta pide a cada DetalleVenta su subtotal, igual que SUM(cantidad * precio_unitario) suma las filas de detalle_ventas.
Lista de comprobación: ¿DetalleVenta calcula su subtotal?, ¿solo Venta crea objetos DetalleVenta?, ¿ControladorVenta no repite la fórmula?, ¿Producto no sabe nada de ventas?

-- Productos vendidos en la venta 1
USE MARKET_DB;
SELECT d.id_venta, p.descripcion,
       d.cantidad, d.precio_unitario,
       d.cantidad * d.precio_unitario AS subtotal
FROM detalle_ventas AS d
INNER JOIN productos AS p ON p.id_producto = d.id_producto
